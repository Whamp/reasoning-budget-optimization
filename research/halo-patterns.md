# HALO patterns for experiment storage + reproducibility

Repo researched: [`context-labs/HALO`](https://github.com/context-labs/HALO) at commit [`471b3a25863f98e4a60fb130d4f7f9421d955981`](https://github.com/context-labs/HALO/tree/471b3a25863f98e4a60fb130d4f7f9421d955981). Scope includes core HALO Engine and the vendored AppWorld demo, which is the repo’s fullest eval-harness example.

## Summary

- **Core HALO is trace-centric, not run-directory-centric:** it consumes a canonical OTLP/OpenInference-shaped JSONL trace file and builds a derived sidecar index. Configs are typed Pydantic objects passed into the engine; outputs are streamed/returned, but not automatically persisted as a run bundle.
- **The AppWorld demo adds a complete eval layout:** `experiments/outputs/<experiment>/` contains traces, config copies, eval reports, task state snapshots, and per-task logs.
- **Most transferable pattern:** make immutable append-only trace JSONL the source of truth, derive query indexes/metrics from it, and store resolved config + eval outputs beside it.

## Evidence by representation

### Configs

- Core HALO config is strongly typed: `EngineConfig` composes root/subagent config, model bindings, provider, trace-index config, compaction knobs, max depth, and parallelism with `extra="forbid"` ([`engine/engine_config.py#L11-L29`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/engine_config.py#L11-L29)). `ModelConfig` captures model name, temperature, max output tokens, parallel tool calls, and `reasoning_effort` ([`engine/model_config.py#L40-L88`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/model_config.py#L40-L88)).
- AppWorld configs are Jsonnet/Jinja-generated and include model settings, seed, `max_steps`, API-predictor config, AppWorld server config, random seed, dataset, and metadata ([template](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/experiments/configs/_generator/templates/openai_agents_mcp_agent.jsonnet.j2#L4-L122); [example](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/experiments/configs/openai_agents_mcp_agent/openai/gpt-4o-2024-05-13/test_normal.jsonnet#L4-L74)).
- AppWorld copies config artifacts into each output directory: rendered JSON plus raw Jsonnet under `experiments/outputs/<experiment>/configs/` ([`cli.py#L1869-L1880`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/src/appworld/cli.py#L1869-L1880)). Caveat: the saved JSON is made before CLI `--override` is applied ([`cli.py#L1819-L1825`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/src/appworld/cli.py#L1819-L1825)); a harness should persist the fully resolved post-override config.

### Trajectories and traces

- HALO’s canonical trace row is one flat `SpanRecord`: top-level OTLP fields are typed; `attributes` and `resource.attributes` remain flexible maps so raw `llm.*`, `tool.*`, and normalized `inference.*` fields survive ([`canonical_span.py#L34-L55`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/traces/models/canonical_span.py#L34-L55)).
- The OpenAI Agents integration writes **one JSONL line per span** on `on_span_end`, including trace/span IDs, timestamps, status, resource, scope, raw upstream attrs, and normalized `inference.*` projections ([docs](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/docs/integrations/openai-agents-sdk.md#L70-L104); [writer](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/telemetry/local_processor.py#L440-L486)).
- AppWorld records a provider-compatible trajectory separately: `Runner.run_streamed(...).to_input_list()` is normalized into dicts and written to `tasks/<task_id>/logs/lm_calls.jsonl` ([`openai_agents/run.py#L153-L184`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/experiments/code/openai_agents/run.py#L153-L184)).
- Parallel AppWorld runs shard traces as `traces-p{process}.jsonl`, then merge them to `traces.jsonl`; HALO indexes by `trace_id`, so merge order is not semantically important ([`run.py#L253-L267`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/experiments/code/openai_agents/run.py#L253-L267); [`Taskfile.yml#L140-L154`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/Taskfile.yml#L140-L154); [README](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/README.md#L120-L132)).

### Trace index, dataset views, and query metrics

- HALO stores a sidecar index row per trace with byte offsets/lengths plus rollups: span count, time bounds, error flag, service/model/agent names, input/output tokens, and project ID ([`trace_index_models.py#L6-L28`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/traces/models/trace_index_models.py#L6-L28)).
- Sidecar meta tracks schema version, trace count, source size, and `mtime_ns`; stale/missing sidecars are rebuilt, and writes are atomic ([meta](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/traces/models/trace_index_models.py#L31-L46); [rebuild logic](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/traces/trace_index_builder.py#L260-L348)).
- Query surfaces are structured: filters are mostly index-only, `DatasetOverview` exposes totals/time ranges/token totals/error counts/sample trace IDs, and search returns bounded match records with `has_more` ([`trace_query_models.py#L8-L179`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/traces/models/trace_query_models.py#L8-L179); [`trace_store.py#L355-L443`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/traces/trace_store.py#L355-L443)).
- Reader APIs are context-budget aware: `view_trace` caps attributes at ~4KB, `view_spans` at ~16KB, both enforce ~150KB response budgets, and oversized responses return summaries with follow-up recommendations ([`trace_store.py#L28-L55`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/traces/trace_store.py#L28-L55); [`trace_store.py#L215-L353`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/traces/trace_store.py#L215-L353)).

### Datasets

- Core HALO treats the trace JSONL itself as the dataset; first engine step ensures/loads the index from the supplied `trace_path` ([`engine/main.py#L69-L73`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/main.py#L69-L73)).
- AppWorld datasets are split text files (`data/datasets/<name>.txt`) listing task IDs; task metadata can filter by difficulty ([`task.py#L248-L290`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/src/appworld/task.py#L248-L290)). Setup downloads 728 tasks across `train`, `dev`, `test_normal`, and `test_challenge` ([README](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/README.md#L31-L39), [splits](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/README.md#L67-L74)).

### Eval outputs, metrics, artifacts

- AppWorld output layout is explicit: traces, config copies, evaluations, server logs, per-task DB snapshots, and per-task `lm_calls.jsonl` ([README](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/README.md#L134-L147)). - Per-task artifacts include `tasks/<task_id>/dbs`, `logs`, `misc`, `version`, and optional `checkpoints` ([`environment.py#L664-L696`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/src/appworld/environment.py#L664-L696)). State snapshots are saved as DB changes with model hashes ([`environment.py#L1274-L1301`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/src/appworld/environment.py#L1274-L1301)). Logs include `api_calls.jsonl` and `environment_io.md` ([`environment.py#L1132-L1150`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/src/appworld/environment.py#L1132-L1150)).
- Eval compares start vs end DB states, calls the task’s ground-truth evaluation module, writes per-task `evaluation/report.md`, and records the AppWorld package version in `evaluation/version.txt` ([`evaluator.py#L452-L520`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/src/appworld/evaluator.py#L452-L520)).
- Dataset metrics are `task_goal_completion` and `scenario_goal_completion`; detailed individual task results are retained under `individual` ([`evaluator.py#L321-L365`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/src/appworld/evaluator.py#L321-L365)). - Trace validation is a simple spec checker asserting required top-level keys, timestamp/status/kind shape, and required `inference.*` fields ([`verify_traces.py#L7-L34`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/openai-agents-sdk-demo/verify_traces.py#L7-L34)); the AppWorld Taskfile wires this into `task verify:traces` ([`Taskfile.yml#L163-L173`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/Taskfile.yml#L163-L173)).

## Transferable patterns for a model-serving/eval optimizer harness

1. **Use append-only span JSONL as the primary run log.** Capture model calls, tool calls, inputs/outputs, token usage, provider/model identity, task/run IDs, and status in each span.
2. **Treat indexes as derived caches.** Build sidecar byte-offset indexes with rollups for cheap filtering; invalidate by schema + source fingerprint; write atomically.
3. **Persist a resolved run bundle.** Adopt AppWorld’s `outputs/<experiment>/` layout, but add a `run_manifest.json` with git SHA, docker/image/package versions, data version, config hash, trace hash, host/provider info, and post-override config.
4. **Shard writes by worker, merge later.** Use per-process `traces-pN.jsonl`/result shards to avoid write contention; make records self-identifying so merge order does not matter.
5. **Store both trajectories and traces.** Keep provider-compatible messages (`lm_calls.jsonl`) for replay/debug and normalized OTLP spans for cross-run analysis.
6. **Make eval machine-readable and human-readable.** Write aggregate JSON + per-task detail JSON/MD/TXT; include metric definitions and version files beside the outputs.
7. **Snapshot mutable environment state.** For serving/eval optimizers, store request/response logs plus state diffs or DB snapshots needed to re-run scoring.
8. **Budget-aware analysis APIs.** Expose overview/query/search/view APIs with byte sizes, truncation markers, and oversized summaries so optimizer agents can inspect large runs safely.

## Gaps/cautions to avoid copying blindly

- Core HALO does **not** persist `EngineConfig` or returned `AgentOutputItem`s as a run artifact; add explicit persistence for optimizer experiments ([`engine/main.py#L251-L269`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/main.py#L251-L269)).
- The trace index meta uses size + mtime, not a content hash; good for local append-mostly logs, weaker for archival reproducibility ([`trace_index_models.py#L31-L38`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/engine/traces/models/trace_index_models.py#L31-L38)).
- AppWorld documents upstream commit/data version for the vendored fork ([`HALO_PATCH.md#L5-L15`](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/HALO_PATCH.md#L5-L15)); do the same for every benchmark dependency.
- AppWorld’s README says fixed `random_seed=100` gives reproducible evals at a fixed `PARALLEL`, but scheduling changes across parallelism settings ([README](https://github.com/context-labs/HALO/blob/471b3a25863f98e4a60fb130d4f7f9421d955981/demo/appworld/README.md#L110-L118)). Treat concurrency as part of the run config.
