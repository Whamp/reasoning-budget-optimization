# Autoresearch reproducibility/storage patterns

Source snapshots inspected:
- `karpathy/autoresearch` @ `228791fb499afffb54b46200aca536f79142f117`
- `davebcn87/pi-autoresearch` @ `84232861a09e753f63bceda46852f0ddbb4c9afd`

## Bottom line

- **karpathy/autoresearch** is deliberately minimal: reproducibility is mostly **git commit + code-as-config + untracked TSV row + `run.log` stdout**. It has no experiment DB and no durable per-run artifact store/checkpoints. Discarded experiments are weakly reproducible because the workflow commits before running, logs a TSV row, then `git reset`s bad commits.
- **pi-autoresearch** is a more transferable harness: durable state is **append-only `autoresearch.jsonl` + human-readable `autoresearch.md` + committed benchmark script**. It embeds session config headers in JSONL, reconstructs state from JSONL, parses structured `METRIC name=value` lines, auto-commits keeps, auto-reverts failures while preserving `autoresearch.*`, and serves dashboards directly from JSONL.
- **No DB layer found in either repo.** pi-autoresearch effectively uses JSONL as the experiment database/index; karpathy/autoresearch uses code/git plus `results.tsv`.

Notable gaps for reproducibility:
- `results.tsv` does **not** embed config, prompt, seed/device metadata beyond a commit hash and description.
- `run.log` is a single filename in the protocol, not a per-run archived artifact.
- No checkpoints/model artifacts are saved by `train.py`; only data/tokenizer prep writes cached files.
- Discard workflow resets bad commits ([program.md#L102-L104](https://github.com/karpathy/autoresearch/blob/228791fb499afffb54b46200aca536f79142f117/program.md#L102-L104)), so failed configs eventually survive only as TSV descriptions/dangling SHAs.

## Transferable patterns for a mobile reasoning-budget harness

1. **Adopt pi-autoresearch’s two-file core:** `experiment.md` for objective/rules/prompt set and `runs.jsonl` as append-only source of truth with config headers/segments.
2. **Embed run config snapshots in JSONL, not only in code.** For mobile budget sweeps, include model/provider, prompt hash/path, reasoning budget, seed, app commit/build, device model, OS, thermal/battery/network state, and evaluator version per run.
3. **Use structured metric lines.** Make the mobile runner print `METRIC primary=value` plus secondary metrics like latency, input/output tokens, reasoning tokens, memory, battery/thermal deltas, crash count, and correctness.
4. **Persist raw artifacts per run.** Improve on both repos: write `runs/000123/{stdout.log,logcat.txt,trace.perfetto,screenshot.png,config.json}` and reference `artifact_dir` in JSONL. Avoid overwritten `run.log` and temp-only full outputs.
5. **Use segments for target changes.** A new prompt set, device, app build, benchmark suite, or primary metric should append a new config header and reset baseline.
6. **Preserve failure information.** Since non-kept code/configs get reverted, require ASI fields (`hypothesis`, `rollback_reason`, `next_action_hint`) and optionally store failed patch/config diffs as artifacts.
7. **Separate correctness checks from primary metric timing.** Run validation after the measured workload; block `keep` on failed checks without contaminating latency/token metrics.
8. **Render dashboards directly from JSONL.** This keeps the harness portable/offline. If a SQLite/DB layer is later needed for querying, still embed config rows and export a JSONL/manifest so artifacts remain self-describing.

Minimal mobile JSONL shape:

```jsonl
{"type":"config","name":"mobile reasoning budget","metricName":"quality_per_1k_tokens","metricUnit":"","bestDirection":"higher","promptSet":"prompts/v1.jsonl","device":{"model":"...","os":"..."}}
{"run":1,"commit":"abc1234","status":"keep","metric":0.82,"metrics":{"latency_ms":1430,"reasoning_tokens":512,"battery_mwh":1.8},"budget":{"max_reasoning_tokens":512},"prompt_ref":"prompts/v1.jsonl#sha256=...","artifact_dir":"runs/000001","description":"baseline 512-token budget","timestamp":1760000000000,"segment":0,"confidence":null,"asi":{"hypothesis":"baseline"}}
```
