# GEPA + DSPy optimizer/persistence patterns

Inspected current `main` snapshots on 2026-05-26:

- GEPA: `gepa-ai/gepa@1f807aa6abdae3bf5caf3bb492f651abecfd0903`
- DSPy: `stanfordnlp/dspy@17928f8150e0c5a3436aff7fbbf0be32442ba9d9`

## Executive takeaways

1. **GEPA’s native abstraction is candidate text maps + opaque evaluator traces.** A candidate is `dict[str, str]`; evaluators return per-example floats and optional traces/outputs/objective scores in `EvaluationBatch`. GEPA only interprets numeric scores; traces are for your adapter/reflection layer. Evidence: [`GEPAAdapter`/`EvaluationBatch`](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/adapter.py#L15-L35), [adapter contract](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/adapter.py#L59-L119).
2. **For non-DSPy expensive black-box evaluation, prefer `gepa.optimize_anything` or a custom `GEPAAdapter`.** `optimize_anything` already normalizes `(score, side_info)` returns, captures logs/stdout/stderr, supports disk cache under `run_dir/fitness_cache`, and injects `opt_state` for per-example warm starts. Evidence: [`SideInfo` contract](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/optimize_anything.py#L173-L232), [evaluator wrapper](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/optimize_anything.py#L1001-L1098), [OA cache/opt_state](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/adapters/optimize_anything_adapter/optimize_anything_adapter.py#L95-L214).
3. **For DSPy programs, `dspy.GEPA` optimizes predictor instructions only.** It compiles a new DSPy `Module`; `track_stats=True` attaches `optimized_program.detailed_results`. Save the compiled program separately with DSPy’s `Module.save(...)`. Evidence: [`GEPA.compile`](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L476-L615), [`DspyAdapter.build_program`](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa_utils.py#L136-L143), [DSPy module saving](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/primitives/base_module.py#L171-L230).
4. **Budget accounting matters for expensive evaluators.** GEPA supports `num_metric_calls` in `EvaluationBatch`; standalone `optimize_anything` sets it when refinement causes multiple evaluator calls. DSPy GEPA’s extra feedback calls inside `make_reflective_dataset` can invoke your metric again and are not explicitly surfaced as `num_metric_calls`; cache inside the metric if the judge is expensive. Evidence: [`num_metric_calls`](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/adapter.py#L31-L35), [reflective budget increment](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/proposer/reflective_mutation/reflective_mutation.py#L254-L270), [DSPy predictor feedback re-calls metric](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L532-L555).

## GEPA API and feedback shapes

### `gepa.optimize(...)`

- Public optimizer signature accepts `seed_candidate: dict[str, str]`, train/val data, either a `GEPAAdapter` or default `task_lm`+`evaluator`, reflection LM/config, budget/stoppers, `run_dir`, W&B/MLflow, `track_best_outputs`, `cache_evaluation`, and `val_evaluation_policy`. Evidence: [`optimize` signature](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/api.py#L43-L96), [logging/cache docs](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/api.py#L163-L181).
- Adapter evaluation return shape: `outputs: list`, `scores: list[float]`, optional `trajectories`, optional per-example `objective_scores: list[dict[str,float]]`, optional `num_metric_calls`. Higher score is better; minibatches use `sum(scores)`, validation uses averages/frontiers. Evidence: [`EvaluationBatch`](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/adapter.py#L15-L35), [scoring semantics](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/adapter.py#L102-L158).
- Reflection feedback shape: `make_reflective_dataset(...) -> component_name -> list[dict]`; recommended record keys are `Inputs`, `Generated Outputs`, `Feedback`, with optional extras such as `score`, `rationale`, `trace_id`. Evidence: [`make_reflective_dataset`](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/adapter.py#L161-L195).
- Default adapter’s evaluator returns `EvaluationResult(score, feedback, objective_scores=None)` and turns trajectories into `{Inputs, Generated Outputs, Feedback}` records. Evidence: [default evaluator](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/adapters/default_adapter/default_adapter.py#L17-L84), [default reflective records](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/adapters/default_adapter/default_adapter.py#L176-L206).

### `gepa.optimize_anything(...)`

- User evaluator returns either `score` or `(score, side_info_dict)`. `side_info["scores"]` is the multi-objective map; other fields are free-form diagnostics; `<param>_specific_info` can target feedback to a parameter; `oa.log()` and `capture_stdio=True` add `log`/`stdout`/`stderr`. Evidence: [`SideInfo` docs](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/optimize_anything.py#L173-L232), [`Evaluator` protocol](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/optimize_anything.py#L387-L440), [`EngineConfig.capture_stdio`](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/optimize_anything.py#L459-L516).
- OA adapter extracts `side_info["scores"]` and parameter-specific scores into GEPA `objective_scores`, then formats reflection records by merging top-level side-info with the component-specific dict; `scores` is renamed to `Scores (Higher is Better)`. Evidence: [objective extraction](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/adapters/optimize_anything_adapter/optimize_anything_adapter.py#L255-L292), [OA reflective dataset](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/adapters/optimize_anything_adapter/optimize_anything_adapter.py#L524-L553).

## GEPA persistence, logs, stats, artifacts

With `run_dir`:

- Default logger writes `run_log.txt`; a `gepa.stop` file acts as graceful stop signal. Evidence: [logger setup](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/api.py#L249-L280).
- Checkpoint files: `gepa_state.bin` pickle, plus human-readable `run_log.json` from `full_program_trace` and `candidates.json`. Save is atomic via temp files. Evidence: [`GEPAState.save`](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/state.py#L306-L347).
- Resume: if `run_dir/gepa_state.bin` exists, GEPA loads it and checks frontier type; cache is preserved/cleared depending on current `cache_evaluation`. Evidence: [`GEPAState.load`](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/state.py#L349-L376), [resume init](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/state.py#L669-L706).
- Best outputs: when `track_best_outputs=True`, GEPA writes `generated_best_outputs_valset/task_{val_id}/iter_{iteration}_prog_{program_idx}.json`. Evidence: [best-output writes](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/state.py#L486-L505), [seed output write](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/state.py#L644-L657).
- Candidate tree: GEPA writes `candidate_tree.html` and logs it to W&B/MLflow when enabled. Evidence: [candidate row/tree](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/engine.py#L264-L279), [HTML artifact](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/engine.py#L880-L890).
- Metrics/tables: scalar metrics include `valset_pareto_front_agg`, `best_score_on_valset`, `val_program_average`, `total_metric_calls`, and `objective/<name>`; tables include `valset_scores`, `valset_pareto_front`, `objective_scores`, `objective_pareto_front`, `candidates`, `proposals`. Evidence: [metric/table logging](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/logging/utils.py#L70-L130), [proposal table](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/engine.py#L818-L878), [W&B/MLflow table/html backends](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/logging/experiment_tracker.py#L284-L358).
- Returned stats: `GEPAResult` contains `candidates`, `parents`, `val_aggregate_scores`, `val_subscores`, Pareto-front mappings, `discovery_eval_counts`, optional `best_outputs_valset`, `total_metric_calls`, `num_full_val_evals`, `run_dir`, `seed`, and `best_candidate`. Evidence: [`GEPAResult` fields](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/result.py#L15-L64), [`from_state`](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/result.py#L233-L271).

Important limitation: rich per-example `trajectories` used for reflection are not a first-class persisted artifact in `run_log.json`; if you need evaluator traces for audit/replay, capture them via callbacks (`on_evaluation_end` includes outputs, trajectories, and objective scores). Evidence: [evaluation callback payload](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/callbacks.py#L102-L125), [callbacks are observational](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/callbacks.py#L256-L262).

## DSPy GEPA API and feedback shapes

- DSPy optimizers are `Teleprompter`s with `compile(student, trainset, teacher=None, valset=None) -> Module`. Evidence: [base `Teleprompter`](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/teleprompt.py#L6-L23).
- `dspy.GEPA` metric must accept five args: `(gold, pred, trace=None, pred_name=None, pred_trace=None)` and return `float` or `ScoreWithFeedback`/`dspy.Prediction(score=..., feedback=...)`. Evidence: [`GEPAFeedbackMetric`](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L27-L56), [constructor signature check](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L373-L379).
- Normal validation uses `Evaluate`, which calls `metric(example, prediction)` and can save CSV/JSON results. Trace/reflection uses `bootstrap_trace_data`, which calls `metric(example, prediction, trace)`. Therefore metric args beyond the first two should have defaults. Evidence: [`Evaluate` call/save/result](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/evaluate/evaluate.py#L170-L225), [`bootstrap_trace_data` trace metric](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/bootstrap_trace.py#L53-L57).
- During reflection, DSPy GEPA calls the metric again with `pred_name` and `pred_trace` to get predictor-level feedback. If only a float is returned, DSPy creates `feedback="This trajectory got a score of ..."`. Evidence: [feedback creator](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L532-L555).
- DSPy currently wants the predictor-level call to return the same module-level score; if it differs, DSPy warns and overwrites it with the module score. Use predictor-specific **feedback text**, not a different score, unless you accept the warning/override. Evidence: [score mismatch handling](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa_utils.py#L291-L307).
- DSPy GEPA’s reflective records are `{Inputs, Generated Outputs, Feedback}`. It can include parse-failure feedback when `add_format_failure_as_feedback=True`; otherwise failed predictions are filtered. Evidence: [`make_reflective_dataset`](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa_utils.py#L198-L319).

## DSPy traces, history, logs, and saving

- Trace shape: `TraceData` has `example`, `prediction`, `trace: list[(predictor, inputs, Prediction)]`, and `score`; `Predict._forward_postprocess` appends `(self, kwargs, pred)` to `dspy.settings.trace` up to `max_trace_size`. Evidence: [`TraceData`](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/bootstrap_trace.py#L22-L41), [`Predict` trace append](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/predict/predict.py#L233-L240).
- LM history is in memory: entries include prompt/messages/kwargs/response/outputs/usage/cost/timestamp/model; history is pushed to global, LM, and caller modules unless `settings.disable_history`. Defaults: `max_history_size=10000`, `max_trace_size=10000`. Evidence: [LM history entry](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/clients/base_lm.py#L167-L187), [history fanout](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/clients/base_lm.py#L374-L399), [settings defaults](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/dsp/utils/settings.py#L15-L36).
- `dspy.GEPA(log_dir=...)` forwards to GEPA `run_dir`; same GEPA artifacts/checkpoint/resume behavior applies. Evidence: [GEPA args docs](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L269-L285), [compile passes `run_dir=self.log_dir`](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L577-L607).
- `track_stats=True` attaches `DspyGEPAResult` to `optimized_program.detailed_results`; fields mirror GEPA stats and rebuild candidates as compiled DSPy modules. Evidence: [`DspyGEPAResult` fields](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L59-L80), [`from_gepa_result`](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L138-L152), [attach stats](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/teleprompt/gepa/gepa.py#L609-L614).
- Save optimized DSPy program explicitly:
  - `program.save("state.json")` or `.pkl` saves state only.
  - `program.save("dir", save_program=True)` saves whole architecture with `cloudpickle` to `dir/program.pkl` + `metadata.json`; load with `dspy.load(path, allow_pickle=True)`.
  - Pickle loading is explicitly unsafe unless trusted. Evidence: [save modes](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/primitives/base_module.py#L171-L230), [state save/load](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/primitives/base_module.py#L232-L292), [`dspy.load`](https://github.com/stanfordnlp/dspy/blob/17928f8150e0c5a3436aff7fbbf0be32442ba9d9/dspy/utils/saving.py#L27-L61).

## Recommended integration pattern for an external expensive evaluator

### If optimizing arbitrary artifacts or non-DSPy agents

Use `gepa.optimize_anything` unless you need a custom program adapter.

- Return `(score: float, side_info: dict)`; keep all scores “higher is better”. Put failure reasons, expected/actual, judge rationale, logs, and external artifact references in `side_info`. Put multi-objective metrics in `side_info["scores"]`.
- Configure `run_dir`, `max_metric_calls`/custom stopper, `cache_evaluation=True`, and for expensive/rate-limited judges set `parallel=False` or a conservative worker count. With `cache_evaluation_storage="auto"`, `run_dir` chooses disk cache; disk cache lives under `fitness_cache`. Evidence: [cache mode resolution](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/optimize_anything.py#L1280-L1313), [disk cache files](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/adapters/optimize_anything_adapter/optimize_anything_adapter.py#L95-L174).
- If one evaluator call may perform multiple external judgments/refinements, set/propagate `EvaluationBatch.num_metric_calls` in a custom adapter so GEPA’s budget is real. Evidence: [reflective proposer counts `num_metric_calls`](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/proposer/reflective_mutation/reflective_mutation.py#L420-L468), [state budget increment](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/proposer/reflective_mutation/reflective_mutation.py#L470-L475).
- Do not throw on per-example failures; return a low score and rich error feedback. Reserve exceptions for systemic failures. Evidence: [adapter error guidance](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/adapter.py#L112-L119).
- Use callbacks to stream audit logs/costs and persist raw traces if needed; GEPA callbacks expose evaluation start/end, valset evaluation, budget updates, and state-saved events. Evidence: [callback events](https://github.com/gepa-ai/gepa/blob/1f807aa6abdae3bf5caf3bb492f651abecfd0903/src/gepa/core/callbacks.py#L102-L245).

### If optimizing a DSPy program with `dspy.GEPA`

- Define metric with defaults: `def metric(gold, pred, trace=None, pred_name=None, pred_trace=None): ...`.
- For expensive LLM/human judges, cache inside the metric keyed by `(gold, pred, pred_name)` or by a stable serialized prediction; DSPy GEPA can call the metric for scoring and again for predictor-specific feedback.
- Return `dspy.Prediction(score=module_score, feedback=rich_feedback)` for feedback calls. Keep `score` equal to the module-level score; put component-specific information in `feedback`.
- Set `log_dir=...`, `track_stats=True`, and optionally `track_best_outputs=True`; pass GEPA passthroughs such as `gepa_kwargs={"cache_evaluation": True, "use_cloudpickle": True}` if useful.
- After compile, persist the optimized module explicitly: `optimized.save("optimized.json")` for state-only, or `optimized.save("optimized_program", save_program=True)` for full architecture.
